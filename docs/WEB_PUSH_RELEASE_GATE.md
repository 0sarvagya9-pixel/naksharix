# Account browser push release gate
References: RFC 8030 and RFC 8292 (https://www.rfc-editor.org/rfc/rfc8292.html), MDN PushManager.subscribe (https://developer.mozilla.org/en-US/docs/Web/API/PushManager/subscribe), Apple Web Push documentation (https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers). Apple permits omission of Content-Encoding for an empty payload.
- Source migration only. WEB_PUSH_ENABLED defaults false. Generate a dedicated P-256 VAPID key pair and a separate random 256-bit endpoint encryption key via approved secret-management tooling; never paste or reuse backup/auth secrets. Key rotation requires explicit device re-registration and revocation of old records.
- Verify the actual FCM, Mozilla and Apple endpoint forms; unsupported providers remain rejected. Do not relax the hostname, HTTPS, redirect or path guards to make testing pass. No payload encryption is needed because the request is empty; the service worker only displays fixed generic account text.
- Test no permission on load, explicit consent, signed-in owner, same endpoint different account, concurrent five-device limit, revoke one/all and sign-out, expired push removal, duplicate status update, malformed ciphertext and key mismatch, 201/202 provider acceptance and actual device display. Already queued notices may arrive after revoke; no private content is included. No marketing sends, synthetic production event, configuration or migration before approval.
